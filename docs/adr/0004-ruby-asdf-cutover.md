# Completed the rbenv→asdf cutover; expose only Ruby's asdf shims on PATH

Supersedes ADR-0002. `languages.sh` now installs a pinned Ruby version via `asdf`, sets it as the global version, and removes rbenv's `PATH`/`init` lines from `.zshrc`/`.zprofile`. The `rbenv` formula itself is uninstalled; `~/.rbenv` is left on disk rather than deleted, as a low-cost rollback path.

Rather than adding the full `~/.asdf/shims` directory to `PATH` (asdf's own documented approach), only Ruby's specific shim files (`ruby`, `gem`, `bundle`, `bundler`, `irb`, `erb`, `rake`, `rdoc`, `ri`, `racc`) are symlinked into a dedicated `~/.asdf/ruby-shims`, which is what actually goes on `PATH`. This machine also has unrelated `python` and `dotnet` asdf plugins installed with no global version set; their shims exist in `~/.asdf/shims` too, and invoking them errors instead of falling through to another `PATH` entry. Exposing the whole shims directory would have broken `python3`/`pip`/`dotnet` the moment this script ran. Adding a new asdf-managed language later means adding its shims to its own narrow directory the same way, not just pointing at `~/.asdf/shims` directly.

**Consequence discovered during the cutover:** `brew uninstall rbenv` auto-removed `libyaml` as "unneeded" (it was only being kept around as ruby-build's build-time dependency). That broke `require 'psych'` at runtime for the asdf-built Ruby, since it's dynamically linked against `libyaml`'s dylib, not just built with it. `libyaml` is now an explicit formula in the Brewfile so `brew autoremove`/`brew bundle cleanup` won't reclaim it again.
